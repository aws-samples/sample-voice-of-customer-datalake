## Reasons

- **Tests the item.** The fake Bedrock refuses the first request with the exact message quoted in the CHANGELOG,
  then answers the second. The test checks three things: exactly two requests were made, the first carried
  `output_config.format` with the schema, and the second carried only the effort. It also checks that the answer
  says it was not structured (`structured` False). The proposal records that flag as `model.structured`, and every
  answer is validated either way. "Once" is pinned by the request count. Two neighbours pin the edges: another
  ValidationException is not retried, and the older format wording still is.
- **Real path.** The product's own `stream_answer` runs, through `run_with_fallback`, `_open` and `_start` and
  `shared/converse.py` `bedrock_call_with_retry`, with its real non-retryable classification. Only the Bedrock client
  (the network edge) and the usage meter's log call (a store write) are faked.
- **Not a tautology.** The expected output configs are literals built from the test's own `SCHEMA` constant and the
  effort it asked for. The refusal message is Bedrock's recorded wording, not a string the product supplies. I also
  checked why the break bites: the old words were `output_config`, `json_schema` and `format`, and the message
  contains none of them ("performance" does not contain "format"). The red run confirms it.
- **Fails on the break.** The ClientError escapes at line 153 instead of a second request being made.
- **Stable.** Green 3/3 after the restore. The test's clock is a fixed tick (`_ticks(0.0)`), and its stream ends at
  once, which stops the heartbeat thread. The test itself has no sleep.
- **Runs in the gate.** `brief` resolved the node, its file holds no skip or xfail mark, and `check` (run after
  `accept`) reports no problem for this test.
