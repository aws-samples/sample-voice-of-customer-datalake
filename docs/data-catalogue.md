# Data catalogue: the processed feedback item

Every review the platform keeps is one item in the `voc-feedback` table (the Silver tier, TENETS.md
D7). This page says what each stored attribute means. `GET /feedback/entities` lists the values a
deployment holds; this catalogue lists what the fields are.

## Read it from the API

`GET /feedback/catalogue` (any signed-in user, metrics Lambda) answers the same catalogue as JSON:

```json
{
  "version": 1,
  "table": "voc-feedback",
  "steps": [{"name": "producer", "meaning": "…"}],
  "policy_effects": [{"name": "redacted", "meaning": "…"}],
  "fields": [
    {
      "name": "urgency", "type": "string", "meaning": "How soon it needs attention",
      "set_by": ["enrichment", "source_update", "reprocess", "edit"],
      "always_present": true, "key": false, "pii": "none",
      "under_redact": "kept", "under_summary_only": "kept",
      "values": ["high", "low", "medium"]
    }
  ]
}
```

- `set_by`: the pipeline steps that write the field, in `steps` order.
- `always_present`: on every stored item; otherwise present only when it applies (the processor
  never stores a null).
- `key`: a table or index key (how an item is found, not what it says).
- `pii`: `customer_text` (the customer's words or a translation of them), `personal` (data about a
  person), `derived_text` (model-written text that may quote the customer), `none`.
- `under_redact` / `under_summary_only`: what the source's PII policy (Administration → Sources →
  source profiles, [source-policies.md](source-policies.md)) does to the field: `kept`, `redacted`,
  `dropped`, `from_redacted` (made from the redacted text) or `replaced`.
- `values`: the allowed values of an enum field, read from the code that enforces them.
  `dimensions` also lists `builtin_dimensions` (the built-in `feedback_type`); the deployment's own
  dimensions are at `GET /settings/dimensions` ([dimensions.md](dimensions.md)). `issue_attributes`
  lists its `sub_fields` from the queue schema (`shared/ingest_schemas.py` `IssueAttributes`).

The catalogue holds no data and no configuration, so it is the same for every caller and changes
only with a release. It is revalidated by ETag like every API GET ([caching.md](caching.md)).

stale. Regenerate it with:

```bash
cd voc-datalake/lambda && ../.venv/bin/python -m shared.feedback_catalogue
```

## Adding a stored attribute

1. Add a `_f(...)` entry to `FIELDS` in `lambda/shared/feedback_catalogue_fields.py`: name, type,
   the steps that set it, its meaning, its PII class, and `always` when every item carries it.
2. An enum's allowed values come from the code that validates them (`_allowed_values` in
   `lambda/shared/feedback_catalogue.py`); never copy the list.
3. A field the source policy redacts or drops goes in `_UNDER_REDACT` (the test checks it against
   `shared/source_policy.py`); a field `summary_only` drops goes in `SUMMARY_ONLY_DROPPED_FIELDS`.
4. Regenerate this page (command above).
